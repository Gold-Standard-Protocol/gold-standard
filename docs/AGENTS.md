# Gold Standard for agents

Everything an autonomous agent needs to use GSUSD with nothing but an Ethereum JSON-RPC
endpoint: where the truth lives, the conventions that must not be guessed, how to read the
protocol, how to act on it, what every refusal string means and which permissionless
calls keep it healthy. No API, no front end and no account are required. Humans find the
same material, with more context, in the docs site and in `docs/SPECIFICATION.md`.

The protocol in one paragraph: GSUSD (Gold Standard Dollar) is an ERC-20 dollar
over-collateralised by tokenised gold. A borrower deposits PAXG into `GoldVault` (XAUT as well once a governance batch activates
it; until then an XAUT deposit reverts), mints GSUSD against it at a minimum ratio of 130% and repays with a per-second stability
fee. Below 110% anyone may liquidate the vault for a 5% penalty, directly or through the
`StabilityPool`. GSUSD holders may swap it for protocol-owned reserve gold in
`GoldStabilityReserve` at a spread that rises as the reserve thins; that right holds
exactly to the depth of the reserve and no further. PAXG and XAUT are issuer claims on
allocated gold, so their issuers sit between a holder and the metal. Every parameter
change passes a timelock whose delay is 48 hours at launch; a change to the delay itself
waits out the delay in force.

The manifest is the record of which networks are deployed. It lists chain id 1 (Ethereum
mainnet) as `not deployed` until the mainnet snapshot exists and carries the mainnet
addresses from then on; Sepolia (chain id 11155111) is the test deployment. Read the status
from the manifest, never from this guide. The manifest is regenerated after every
deployment and parameter change (`docs/MAINNET.md` section 4.1).

### Verify before you trust

An address in a chat, a page or a search result is a claim, not a fact. Before sending
value, confirm the set is self-consistent on chain:

1. `GoldStablecoin.hasRole(MINTER_ROLE, vault)` is true for the vault in the manifest.
   Only the vault holds `MINTER_ROLE`. A stablecoin deployed from 2026-11-06 on is
   `AccessControlEnumerable`, so you can read the whole set rather than one holder:
   `getRoleMemberCount(MINTER_ROLE)` is 1 and `getRoleMember(MINTER_ROLE, 0)` is the vault.
   The minter set stays changeable by governance through the timelock until
   `lockMinters(vault)` is called (`lockMinters()` on earlier deployments), which on the
   enumerable stablecoin succeeds only while the vault is the sole minter, and
   `GoldStablecoin.mintersLocked()` tells you whether that has happened. The manifest's
   per-network `minting` entry says what the snapshot recorded and adds a `mintersLocked()`
   check to the list only once it is true.
2. `GoldVault.vaultRegistry()` returns the registry in the manifest and
   `VaultRegistry.vault()` returns the vault.
3. `GoldVault.stabilityPool()`, `GoldVault.stablecoin()` and `GoldVault.oracle()` match.
4. `hasRole(DEFAULT_ADMIN_ROLE, timelock)` is true on the vault and the stablecoin and
   the deployer no longer holds it (`governanceTransferred` in the snapshot).
5. The bytecode at each address is verified on Etherscan against the published source.
6. `SurplusBuffer.absorptionBurns()` returns true. Only the current contract generation
   answers it, so a set still running older code fails here instead of passing on its wiring.

The manifest carries these checks ready to replay: each network's `verification` list is a
set of `eth_call`s with the name of the address it targets (`address`, a key of the
network's `addresses`), the target itself (`to`), the calldata and the exact 32 byte word the
call must return, so an agent with no ABI can prove the set is self-consistent before
anything else. Every address in the set is the target of at least one call, and every
expected word is derived from the deployment snapshot, so a look-alike set that merely points
at the real contracts cannot satisfy the list the protocol publishes. The list proves that a
set agrees with the manifest it came in, not that the manifest is genuine: whoever writes a
look-alike set can write a list to match it. So take the manifest from
`https://goldstandardfinance.eth.limo/agents.json` or this repository, compare its addresses with an
address book you already trust, build the wiring checks of steps 1 to 3 from the addresses
yourself and only then replay the list, reading its labels as the manifest's claims. Treat
the list as a whole: refuse the set when the list is empty, when any listed address has no
call that targets it, when a call's `to` differs from the address it names or when any call
returns a different word.

`tools/agent-quickstart.mjs` in the repository does exactly that. A manifest from anywhere
but this tree must name exactly the addresses in the address book committed for its chain
(`contracts/deployments/<network>.json`), and is refused when no book exists for that chain.
Any manifest is refused when the entry filed under a chain describes a different chain, so
the address book and the RPC always answer for the same one. The tool then runs its own
wiring checks, with calldata, labels and expected words it builds from the addresses,
replays the manifest's list with every label printed as a manifest claim, prints how many
addresses it verified and lists every open vault with its state. The book anchors
addresses alone, so for a manifest from elsewhere the network name, generation date, deploy
block, collateral symbols, ratios, active flags and notes are printed as its claims, on lines
that begin `manifest claim:`. Every manifest string it quotes, in a claim or in a refusal,
is printed on a single line with its control characters and Unicode bidirectional controls
escaped. An address that is neither all lower case nor a valid EIP-55 checksum is refused, and
so is a manifest that is not JSON, which is never quoted. The prices the oracle returns are printed as fact against the
token address the oracle reports, the manifest's decimals are never used and each vault's
collateral is shown in the token's base units. It is the smallest honest client of the protocol and a worked
example of sections 1 to 3.

## 2. Conventions that must not be guessed

| Convention | Value |
|------------|-------|
| Ratios | parts per million; 1,000,000 is 100%, 1,300,000 is 130% |
| Prices | USD per whole token with 8 decimals, from `GoldOracle` |
| GSUSD | 18 decimals, ERC-20 with `permit` (EIP-2612) |
| Collateral amounts | the token's own decimals: PAXG 18, XAUT 6. Read `decimals()` from the token; never assume |
| Debt | `getVaultCurrentDebt(owner)` includes the accrued stability fee; `vaults(owner).debtAmount` does not |
| Repay | `repay(amount)` caps at the current debt, so an overshoot closes the position cleanly |
| Liquidate | `liquidate(owner, 0)` and `liquidateViaPool(owner, 0)` repay the whole debt; a positive amount is a partial |
| Minimum debt | `GoldVault.minDebt()`, governed; 100 GSUSD on Sepolia, 1,000 at the mainnet launch. A mint or partial repay that leaves less is refused |
| Deposits | the vault credits what arrives, so a fee-on-transfer token credits less than was sent |
| Gas | the vault requires at least 375,000 gas left before its registry hook, so an estimate from a real node already includes it; send the estimate with a buffer, never a hand-picked limit. A local development node whose estimator probes above its own per-transaction cap can fail to estimate a vault write; there, find the limit by simulating with `eth_call` at rising gas limits under the cap |
| Pauses | `paused()` on the vault, the oracle and the pool; every pause lapses 14 days after it was set unless extended, and `unpauseExpired()` is permissionless once `pauseExpiresAt()` has passed. A reserve asset is paused while `GoldStabilityReserve.assetPaused(token)` is true; that pause lapses by itself at `assets(token).pausedUntil`, 14 days after the guardian last paused it. `pauseEpoch()` on each pausable contract and `assetPauseEpoch(token)` on the reserve number the pauses (every pause, extension, renewal and bad-debt breaker trip takes a new number): a governance unpause must name the current one |

## 3. Read the protocol

All reads are `view` calls. `VaultRegistry` is the entry point: `GoldVault` maintains it
after every deposit, withdrawal, mint, repayment and liquidation, so it lists exactly the
vaults that hold collateral or debt.

| Question | Call |
|----------|------|
| How many vaults are open, and whose | `VaultRegistry.vaultOwnerCount()`, then `vaultOwners(offset, limit)` in pages |
| One vault at a glance | `VaultRegistry.vaultSummary(owner)` returns `token`, `collateral`, `debt`, `ratio` (ppm, max uint when debt-free), `liquidationPrice` (8 decimals) and `liquidatable` |
| Which vaults are liquidatable now | `VaultRegistry.liquidatableVaults(offset, limit)` or `isLiquidatable(owner)` are hints priced at `lastKnownPrice`, which nothing refreshes in a quiet market, so they can miss a vault while the price falls. The test `liquidate` applies: `collateral × 10^(18 − decimals) × quoteTokenPrice(token) / 1e8 × 1e6 / getVaultCurrentDebt(owner) < liquidationRatio` |
| Is a vault in or out | `VaultRegistry.isVaultOwner(owner)` |
| Collateral rules for a token | `VaultRegistry.collateralTypeOf(token)`: `minRatio`, `liquidationRatio`, `liquidationPenalty`, `debtCeiling`, `totalDebt`, `active` |
| Current debt including fees | `GoldVault.getVaultCurrentDebt(owner)` |
| Stability fee | `StabilityModule.stabilityFeeRate(VaultRegistry.collateralIdOf(token))`: the per-second multiplier with 18 decimals (1e18 is no fee). Debt grows by it every second, so a debt read now is short by the time a transaction lands |
| Origination fee | `GoldVault.originationFeeBps()`, taken from what a mint delivers unless `originationFeeExempt(account)`; the debt still rises by the full amount minted |
| Most a vault may mint | collateral value at `quoteBorrowPrice(token)` (`collateral × 10^(18 − decimals) × price / 1e8`) × 1e6 / `minRatio`, less `getVaultCurrentDebt(owner)`, and within `debtCeiling − totalDebt` where governance has set a ceiling |
| Ratio and liquidation price | `GoldVault.getCollateralisationRatio(owner)`, `GoldVault.getLiquidationPrice(owner)` |
| A usable price | `GoldOracle.quoteTokenPrice(token)` is the liquidation price and `quoteBorrowPrice(token)` the borrowing price, as views with the same reverts as the calls they mirror; act only when they answer. `getValidatedPrice(token)` returns `(price, ok)` for the market feed alone, so it cannot tell you whether the gold reference is healthy |
| Pool position | `StabilityPool.getEffectiveDeposit(user)`, `getCollateralGain(user, token)`, `getTotalDeposits()` |
| Swap terms | `GoldStabilityReserve.quoteGoldOut(token, gsusdIn)` returns `(goldOut, spreadPpm)` at the spread tier this swap pays, which is the tier of the coverage the swap leaves behind; `(0, 0)` means the swap would be refused: the asset is unsupported or paused, or the oracle gives no reserve price. The quote does not apply the floor or the daily caps, so bound the size with `remainingDailyCapacity(token)`, which honours the floor, the per-asset cap and the aggregate USD cap when it is on, and reads 0 whenever a swap would be refused (asset paused, token frozen, oracle paused, no reliable price), and `redeemableCollateral(token)` |
| Reserve health | `GoldStabilityReserve.coveragePpm()`, `dampedCoveragePpm()`, `reserveValueUsd()`. `currentSpreadPpm()` is the spread of a vanishingly small swap; size a real one with `quoteGoldOut` |
| Supply | `GoldStablecoin.totalSupply()` and `smoothedSupplyNow()` (the one-day smoothed total). The reserve prices its spread against `GoldStabilityReserve.dampedCirculatingSupply()`: the higher of `circulatingSupply()` (supply less the reserve's own GSUSD) and the smoothed supply less that inventory |
| Pause state | `paused()` and `pauseExpiresAt()` on each pausable contract; `assetPaused(token)` on the reserve |

## 4. Act on the protocol

Simulate every call with `eth_call` from the sending address before sending it; the
refusal strings in section 6 are exact and stable. Approve only what the next call needs.

### Open and manage a vault

1. `token.approve(vault, amount)`, then `GoldVault.deposit(token, amount)`. One vault per
   address, one collateral token per vault.
2. `GoldVault.mint(amount)` in GSUSD. Refused below 130%, below `minDebt`, over the
   collateral's debt ceiling or the per-block mint cap where governance has set them (mainnet
   launches with neither), while the vault is paused or when the oracle refuses a borrowing
   price ("Off gold band", "No reliable price"). Borrowing values the collateral at the lower
   of the market feed and XAU/USD, and only while the market feed sits within the gold band
   (2% at launch) of XAU/USD. Size the mint from the "Most a vault may mint" read in
   section 3 with a margin of your own. Where `originationFeeBps()` is above zero the
   fee is taken from what the mint delivers.
3. `GSUSD.approve(vault, amount)`, then `GoldVault.repay(amount)`. Partial repayments must
   leave at least `minDebt`; an amount above the debt repays it exactly. For a full
   repayment, approve and pass the current debt plus a small margin (the stability fee
   for a few minutes is ample): the vault takes only the debt at the moment of execution,
   so an exact approval of a debt read earlier falls short with `ERC20InsufficientAllowance`.
   Reset the allowance to zero afterwards. The accrued fee means a full repayment needs
   more GSUSD than was minted; this guide does not name a venue for acquiring it.
4. `GoldVault.withdraw(amount)` in the collateral token's decimals. Refused if the remaining
   ratio would fall below 130%; a withdrawal to zero with no debt closes the vault and
   removes it from the registry. While the vault is paused only a full repayment unlocks
   withdrawal.

### Liquidate

Direct: hold GSUSD, `GSUSD.approve(vault, debt)` with a small margin for the fee that accrues
until inclusion, then `GoldVault.liquidate(owner, 0)`.
The call burns your GSUSD, pays you collateral worth the debt plus 60% of the 5% penalty
straight from custody and routes the rest of the penalty to the protocol. Refused above
110% ("Not undercollateralised"), when the oracle refuses a price ("No reliable price",
"Token frozen"), when a partial would leave the vault
with less than `minDebt` ("Residual debt below minimum"), when an underwater vault is asked
for a partial ("Thin vault: liquidate in full") or when the seizure would round to nothing
("Liquidation too small"). Liquidation, its trigger and its seizure alike, prices the
collateral at min(max(C, G), G × (1 + m)): C the token's market feed, G Chainlink XAU/USD and
m the liquidation cap (2% at launch). A push of the market feed down therefore values the
collateral at gold at worst, and a depeg specific to the token is not liquidated while gold
holds. With either feed stale or invalid liquidation waits and resumes by itself on the
first healthy pair; nobody has to call anything. A vault is thin below 100% plus the penalty: there a partial is
taken pro rata (the seizure is the collateral times the share of debt repaid, so the ratio
does not change), and below 100% only a full liquidation is accepted. The pool path keeps
working while the vault is paused, priced by the emergency rule. When a
vault is under water the seizure is sized at a governed discount (`underwaterDiscountPpm`)
so the liquidator is still paid. The discount (2% at launch) is split like the penalty, 60%
to the liquidator and 40% to the protocol, so a direct liquidator's margin on an underwater
vault is at most 1.2%; a pool liquidation pays its caller half of the liquidator share. The
discount never exceeds the shortfall: a vault a hair
under water sells at almost exactly its value, so nobody, the borrower included, can collect
the full discount from the insurance buffer on a vault that is barely insolvent. An underwater
vault repays less than its nominal debt, and `liquidateViaPool` needs the pool to hold more
than that repayment, not more than the debt.

Through the pool: `GoldVault.liquidateViaPool(owner, 0)` needs no GSUSD of your own. The
`StabilityPool` burns its deposits, its depositors receive the collateral and the caller
receives 30% of the penalty, paid in the collateral token. Refused when the pool cannot
cover the debt ("Pool insufficient"); fall back to the direct path. A liquidated vault
keeps any collateral left after the seizure and stays listed until its owner withdraws it.

While the vault or the oracle is paused (by the guardian or the bad-debt breaker) the direct
path is closed. Two paths run then: `liquidateViaPool` as above, and
`GoldVault.emergencyLiquidate(owner, debtToRepay)`, which runs only during a pause. Neither
runs for a token the guardian or governance has frozen ("Token frozen"): a pause does not
lift a freeze.

### Provide to the stability pool

`GSUSD.approve(pool, amount)`, `StabilityPool.deposit(amount)`. `withdraw(amount)` is
refused in the block of the deposit ("No same-block withdrawal") and while the pool is
paused. `claimCollateral(token)` collects the gold gained from liquidations, up to what the
pool holds in that token; anything it cannot pay stays owed and is paid by a later claim. A
claim is refused in the block of the caller's latest deposit as well ("No same-block
claim"), a top-up included, and is not stopped by a pause: a contract that deposits and
claims in one transaction always reverts, so send the claim in a later block. Depositors carry
the risk of a depeg in one gold token: liquidation values collateral at gold at worst, so
while a token trades below gold the pool pays the debt for collateral worth less at market
(about 7% of the absorbed debt at a 10% depeg).

### Swap GSUSD for reserve gold

`quoteGoldOut(token, gsusdIn)` for the exact size you will send (a larger swap can pay a
dearer spread tier), then `GSUSD.approve(reserve, gsusdIn)` and
`GoldStabilityReserve.swapGsusdForGold(token, gsusdIn, minGoldOut)` with `minGoldOut`
from the quote less your tolerance. The reserve sells at the higher of the market feed and
XAU/USD, and only while the market feed sits within the gold band, so a swap is refused
with "Off gold band" during a depeg specific to the token and "No reliable price" while
either feed is stale. It is also refused when the asset is paused, when the daily or
aggregate cap is reached, when the reserve cannot deliver ("Reserve insufficient") or
when the output would be below `minGoldOut` ("Slippage"). The swap draws only on
protocol-owned gold and never touches a borrower's vault. The reserve sells gold for
GSUSD only; it does not sell GSUSD.

## 5. Permissionless maintenance

These calls need no role. Each protects the protocol or a position. The oracle itself needs
no maintenance call: no observation, no heartbeat and no record to keep, and liquidation
resumes by itself on the first healthy pair of feeds.

| Call | When |
|------|------|
| `GoldOracle.getTokenPrice(token)` | refreshes `lastKnownPrice`, the record behind the vault's views and the registry's hints, when nothing else has priced the token for a while (a transaction, not a view); permissionless and harmless. The record never prices a seizure |
| `VaultRegistry.sync(owner)` or `syncMany(owners)` | a `VaultRegistrySyncFailed` event from the vault shows a listing drifted; the registry re-reads the vault and corrects itself |
| `unpauseExpired()` | `pauseExpiresAt()` has passed on a paused contract |
| `GoldVault.retryBadDebtAbsorption()` | `GoldVault.totalBadDebt()` is above zero and `SurplusBuffer.gsusdBalance()` is above zero again. The buffer counts only fees banked through `depositFee` (origination and stability fees from the vault, the swap spread from the reserve), never a plain GSUSD transfer, which stays uncounted for good. Refused with `No buffer`, `No bad debt` or `Nothing absorbed` |
| `SiloFactory.createSilos(token, count)` | `SiloFactory.missingSilos(token)` is above zero, which happens only after governance has moved the deposit cursor past a run of unusable silos. It creates the silos the next deposit would otherwise create itself, at most 16 a call (`count` from 1 to 16). Read `missingSilos(token)` before every call and stop at 0: the call reverts `Nothing to create` when nothing is missing and `Unknown token` for an address the factory has no silo for. It moves no funds |
| `StabilityModule.accrueInterest(collateralId)` | optional: brings the fee accumulator up to date. Every read already projects the fee to now, so no position depends on it |

## 6. Refusal strings

Reverts carry short reason strings. The ones an agent meets:

| String | Meaning |
|--------|---------|
| `Zero amount` | an amount of zero |
| `Nothing credited` | `GoldVault.deposit` whose transfer delivered nothing to custody (a token transfer fee that takes a dust amount whole); the call reverts and nothing is taken |
| `Unknown token`, `Nothing to create`, `Invalid count` | `SiloFactory.createSilos`: the address has no silo and its cursor was never moved; no silo is missing (a deposit or another caller may have filled the gap first); `count` is outside 1 to 16 |
| `Collateral type not active`, `Collateral token mismatch` | the token is not accepted for new deposits, or the vault already holds the other token (one token per vault) |
| `No collateral` | mint before any deposit |
| `Insufficient collateral` | a withdrawal above the vault's collateral |
| `No debt`, `Exceeds vault debt` | a repayment or liquidation of a vault with no debt, or a partial liquidation above the current debt |
| `Below min collateralisation ratio` | the mint would leave the vault under 130% |
| `Below min ratio` | the withdrawal would leave the vault under 130% |
| `Below minimum debt`, `Remaining debt below minimum` | the position would be smaller than `minDebt` |
| `Debt ceiling reached` | the collateral's governed ceiling is full |
| `Per-block mint cap reached` | mint again in a later block |
| `Not undercollateralised` | the vault is at or above 110% at the validated price |
| `Stale oracle`, `Invalid price` | the legacy `getPaxgPrice` or `getXautPrice` read refused its feed; do not retry blindly |
| `No price` | the emergency path found no liquidation price: the market feed or XAU/USD is stale or invalid. `lastKnownPrice` never stands in |
| `Residual debt below minimum` | the partial would leave less than `minDebt`; size it differently or repay in full |
| `Thin vault: liquidate in full` | the vault is under water (gold worth less than its debt), so only a full liquidation is accepted; between 100% and 100% plus the penalty a partial is taken pro rata |
| `Liquidation too small` | the seizure rounds to nothing |
| `Mint amount too large` | the mint would overflow the vault's debt arithmetic; no honest amount reaches it |
| `Min ratio exceeds maximum` | a governance proposal set a minimum ratio above the vault's cap (1,000%) |
| `Not a contract`, `Reserve has not granted VAULT_ROLE`, `Registry serves another vault` | wiring refusals from the governance setters: a module address with no code, a reserve that has not granted the vault its role, a registry built for another vault |
| `Wrong contract` | the governance wrapper was asked to adopt a replacement vault, oracle or stability module that holds code but does not answer that kind's read; a replacement with no code answers `Not a contract` |
| `Self payment` | a governance withdrawal from the vault's surplus, the surplus buffer or the reserve named the paying contract itself as the recipient, or the fee splitter was named as its own beneficiary; nothing moves and no ledger changes |
| `Decimals must be 2 to 18`, `Silo cap rounds to zero` | a collateral token with fewer than two or more than eighteen decimals cannot be listed; the silo factory answers the second if such a token ever reaches it |
| `Pool insufficient` | the pool holds no more than the repayment it would make (the debt, or the discounted repayment for an underwater vault); use the direct path |
| `Paused: repay in full to withdraw` | the vault is paused |
| `Not in emergency` | `emergencyLiquidate` only runs while the vault or oracle is paused; a frozen token answers `Token frozen` first |
| `Token frozen` | the guardian or governance has frozen this token as an emergency stop: minting, indebted withdrawals, swaps and every liquidation in it wait, during a pause as well, until the freeze is lifted (`guardianUnfreezeToken(token, freezeEpoch(token))`) or lapses after 14 days (`frozenUntil(token)`); repaying and depositing still work |
| `Off gold band` | the token's market feed sits more than the gold band (`goldBandPpm(token)`, 2% at launch) from XAU/USD; borrowing and reserve swaps in that token wait, while liquidation still prices it, at gold at worst |
| `No reliable price` | the token's market feed or XAU/USD is stale or invalid; borrowing, swaps and liquidation in that token wait and resume by themselves on the first healthy pair, repaying and depositing still work |
| `No oracle feed` | the reserve refuses to list a token the oracle cannot price |
| `No same-block withdrawal` | pool withdrawals wait one block after the caller's latest deposit |
| `No same-block claim` | `claimCollateral` waits one block after the caller's latest deposit, a top-up included; the gain stays owed |
| `No gains` | `claimCollateral` with nothing to collect in that token |
| `No collateral held` | `claimCollateral` with gains owed but none of that token left in the pool (an issuer wipe); the gains stay owed |
| `Unsupported token` | a token the oracle, the pool or the reserve does not list |
| `Withdrawal failed: insufficient unfrozen silo balance` | the token's issuer has frozen part of the custody; the rest stays withdrawable and the frozen part again once the issuer lifts its freeze |
| `Asset paused`, `Invalid price`, `Swap too small`, `Slippage`, `Reserve insufficient`, `Daily cap reached`, `Aggregate daily cap reached` | swap refusals, in the order the reserve checks them |
| `Registry gas` | the transaction carried less gas than the vault's registry hook needs; send a real estimate |
| `Pause not expired`, `Not paused` | `unpauseExpired` called too early, or on a contract that is not paused |
| `Different pause` | `unpause(epoch)` or `unpauseAsset(token, epoch)` names an earlier pause than the one in force |
| `Different freeze`, `Not frozen` | `guardianUnfreezeToken(token, epoch)` names an earlier freeze than the one in force (`freezeEpoch(token)`), or the token is not frozen |

Custom errors come from OpenZeppelin: `AccessControlUnauthorizedAccount` for a role you
do not hold, `ERC20InsufficientAllowance` and `ERC20InsufficientBalance` for approvals and
balances, `EnforcedPause` from a paused contract.

## 7. Operating rules for an agent

- Treat `agents.json` as the address book and run the whole verification list in section 1
  once per session; refuse the set if the list is empty, leaves an address unproven, targets
  an address other than the one it names or returns a different word. Cache nothing across a
  redeploy: the manifest's `deployBlock` changes.
- Read `quoteTokenPrice(token)` before any liquidation, size the seizure from it and skip the
  token while it reverts.
- Walk the registry in pages of a few hundred and read `vaultSummary` for each owner
  (batched through Multicall3 at its canonical address `0xcA11bde05977b3631167028862bE2a173976CA11`
  where the chain has it). Decide liquidatability with the test in section 3 at
  `quoteTokenPrice`, not with the `liquidatable` hint alone. The owner set is permissionless,
  so expect dust vaults.
- Liquidations are competitive. Simulate, send with a real gas estimate plus a buffer and
  expect `Not undercollateralised` when another liquidator was first.
- Keep approvals short-lived: approve what the next call needs (with the fee margin for a
  repayment or liquidation) and reset to zero afterwards. GSUSD supports `permit`
  (EIP-2612), so the allowance can be set by signature instead of an `approve`
  transaction; the vault, the pool and the reserve have no entry point that takes a permit,
  so the permit and the call are still two transactions.
- Mind the timelock: a parameter you read today can change once a scheduled proposal has
  waited out the delay in force, 48 hours at launch; `TimelockController.getMinDelay()` is
  the live value. The timelock's `CallScheduled` events announce every change, including
  one scheduled on the timelock directly rather than through `GoldGovernance`, and a change
  to the delay itself emits `MinDelayChange` when it executes. Six vault setters
  (`setOracle`, `setLiquidatorIncentiveShare`, `setSurplusBuffer`, `setStabilityPool`,
  `setSiloFactory`, `setBadDebtPauseThreshold`) emit no event of their own: the timelock's
  `CallScheduled` and `CallExecuted`, which carry the target and the call data, are how
  those changes are seen. On a timelock deployed from
  2026-11-06 on, a scheduled change takes effect only if it is executed within 7 days of
  becoming ready (`GRACE_PERIOD` on the timelock); after that `isOperationExpired(id)` is true and it can never execute, so treat
  an expired `CallScheduled` with no `CallExecuted` as a change that will not happen.
- Never claim more than the contracts do. GSUSD is over-collateralised, not backed one for
  one; the swap is a priced right that holds to the depth of the reserve; the collateral
  carries its issuers' counterparty risk.

## 8. Why this exists

An agent that can read a balance sheet should not need a web page to use a currency. The
registry gives it the list of positions, the views give it the state, the refusal strings
give it the rules and the timelock gives it notice of change. Everything an agent or a
human does through the dapp can be done with these calls alone, and the dapp is only a
rendering of them.
